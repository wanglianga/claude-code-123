# 基层法院诉前调解排期与协议履行平台

面向基层法院的诉前调解一体化平台：当事人在线提交申请 → 立案窗口分流 → 调解中心按案由/专长/双方时间/外地当事人智能排期 → 调解员线上线下调解并记录 → 协议人脸核验与线上签署 → 分期履行跟踪与逾期预警 → 回访、司法确认或转立案。**所有角色围绕同一案件推进，全部过程统一进入案件时间线，多次改期、失联、部分履行等情形可一键汇编成连续材料卷提交法官，避免在调解与立案窗口间反复补材料。**

## 技术栈

- 后端：Java 17、Spring Boot 3.2、Spring Data JPA
- 数据库：**默认 H2 内存库（MySQL 兼容模式），免安装零配置**；同时提供 MySQL 连接配置
- 前端：Vue 3 + Vite + Element Plus + ECharts
- 鉴权：登录令牌（内存 Token 存储，Bearer 头）

## 本地启动

### 方式一：单 jar 启动（推荐，已构建好前端产物）

前置：JDK 17、Maven 3.8+。

```bash
cd backend
mvn package -DskipTests
java -jar target/mediation-platform.jar
```

浏览器打开 <http://localhost:8080/> 即可（前后端同源，无需额外启动前端）。
H2 控制台（可选）：<http://localhost:8080/h2-console>，JDBC URL `jdbc:h2:mem:mediation`，用户名 `sa`，密码空。

### 方式二：前后端分离开发（热更新）

```bash
# 终端1：后端
cd backend && mvn spring-boot:run

# 终端2：前端（5173 端口，/api 自动代理到 8080）
cd frontend && npm install --cache /tmp/npm-cache && npm run dev
```

打开 <http://localhost:5173/>。

### 使用 MySQL（可选）

1. 本机 MySQL 8，账号 root/root（或修改 `application.yml` 中 `mysql` profile 的用户名密码）；
   连接串带 `createDatabaseIfNotExist=true`，库 `court_mediation` 会自动创建，表由 JPA 自动建立。
2. 以 mysql profile 启动：

```bash
cd backend
mvn spring-boot:run -Dspring-boot.run.profiles=mysql
# 或 jar 方式：java -jar target/mediation-platform.jar --spring.profiles.active=mysql
```

## 业务功能与对应操作

1. **申请登记**：「新建调解申请」记录五类案由（民间借贷/物业费/交通事故/邻里/小额买卖）、诉求金额、被申请人联系方式、证据清单、是否愿意线上调解、紧急程度、外地当事人标识。
2. **窗口分流**：案件详情 →「分流与排期」，核验材料（缺件可先行调解并登记补正）、确定线上/线下（外地当事人自动提示线上）、从名册指派调解员。
3. **智能排期**：选择时间段后系统按「案由专长匹配 + 在办量 + 时间冲突」综合打分推荐调解员；排期自动检测调解员时段冲突；每次**改期保留原记录**、累计改期次数，≥2 次触发红黄预警。
4. **调解过程**：逐次记录争议焦点、双方让步、协商过程与结果；支持电子送达（短信/邮件/站内，无有效号码自动失败留痕）、失联登记/恢复、证据补正。
5. **协议与签署**：起草协议（一次性/分期、付款计划、担保人、履行期限、是否申请司法确认，自动生成规范文本）→ 模拟人脸核验（任意非 `0000` 的证件后四位通过，`0000` 演示不通过）→ 双方线上电子签名，签后协议生效。
6. **履行跟踪**：按协议生成一期或多期付款节点；执行联络确认到账，支持**部分履行**；定时任务每日扫描到期未付节点自动置逾期并预警（页面也提供「立即扫描逾期」按钮用于演示）。
7. **回访**：执行联络/法官助理登记电话/线上/上门回访与结果。
8. **司法确认**：申请后案件进入审查中，可下载《司法确认申请书》，法官助理审查通过后转入履行跟踪。
9. **转立案**：选择失联/证据争议/拒绝调解/协议逾期等原因，系统**自动汇编**申请、分流意见、历次排期改期、笔录、协议签署、履行、回访、送达、失联说明为材料包，窗口一次接收并登记诉讼案号，当事人无需重复补交。
10. **连续过程材料卷**：案件详情页「导出连续过程材料卷」随时把全过程时间线汇编成文本下载，供法官查阅。
11. **批量导入**：「批量导入」页支持 CSV 文件上传或粘贴，自带模板，逐行返回成功编号与失败原因。
12. **统计看板**：调解效率（成功率、在办、待分流）、案由分布、状态分布、协议履行到位率/已付总额/逾期节点、转立案原因分布、多次改期/失联/缺件风险统计（ECharts 图表）。
13. **角色工作台**：登录后首页按角色生成待办（窗口待分流/材料待接收、调解员待排期待调解失联联系、当事人出席确认/逾期告知、法官助理司法确认与转立案审核、执行联络分期与逾期回访）。

### 手工快速复验建议

- 用 `window/window123` 登录打开待分流案件，完成一次分流与排期；
- 用 `party/party123` 登录可见自己作为申请人的案件；
- 在任意调解中案件走「笔录 → 协议 → 人脸（输 1234）→ 双方签署 → 分期计划 → 部分到账 → 立即扫描逾期」；
- 打开「统计看板」查看图表；「导出连续过程材料卷」核对时间线连续性。

## 说明与边界（演示环境）

- 人脸核验、电子送达、电子签名为**业务流程级模拟实现**（返回确定性模拟结果并完整留痕），接入真实能力时替换 `MediationService.faceVerify`、`DeliveryService.send` 即可，表结构已预留核验得分/证件后四位/送达签收字段。
- 令牌存于内存，服务重启需重新登录；H2 为内存库，重启后数据由种子程序重新初始化。
- 金额单位均为人民币元；时间为服务器本地时间。
